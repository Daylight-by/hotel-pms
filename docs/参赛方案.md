# 酒店 PMS · 大创赛参赛方案（获奖导向）

> 目标只有一个：**拿奖**。因此本文件优先于原「商业化交付」思路。
> 凡是与「演示效果 / 创新叙事 / 答辩说服力」无关的功能，一律降级或砍掉。

## 一、评分维度拆解与对策

大创赛评委（校/省/国）看的四类，对策如下：

| 评分维度 | 评委实际在看什么 | 我们的对策 |
|---|---|---|
| **创新性** | 跟市面上比，你新在哪 | 立四张牌（见第三节），其中「智能定价」是核心差异点 |
| **可行性** | 是不是真做出来了，跑不跑得起来 | P0 + P1 完整可跑，端到端闭环能当场演示 |
| **商业性** | 谁会用、为什么用、怎么赚钱 | 定位中小酒店空白市场，配商业计划书三件套 |
| **答辩表现** | 讲不讲得清、演示顺不顺 | 数据大屏 + 演示数据 + 剧本 + 小程序体验版 |

**最重要的判断**：评委记不住你做了二十个功能，只记得住**一两个亮点**和**演示那几分钟**。
所以资源向「一个真亮点 + 一场好演示」倾斜，而不是铺功能。

## 三、创新点叙事（四张牌）

评委必问「跟市面产品比新在哪」，按这个顺序讲：

### 牌 1：市场定位 —— 中小酒店的空白（最好讲，先讲）

- 80 间房以下的中小酒店：SaaS（如绿云、别样红）按房量年费贵且数据上云；
  传统本地软件（如西软、中软）重、贵、实施周期长
- 我们：**开源 + 轻量 + 可本地部署**，数据不出酒店，零软件采购成本
- 一句话：「让买不起 PMS 的小酒店也用得上 PMS」

### 牌 2：智能定价 —— 收益管理下沉（技术核心，重点讲）

这是本项目**唯一的算法亮点**，必须做，且要讲得清：

- 痛点：中小酒店老板不懂收益管理，房价常年不变，旺季不涨、淡季不降
- 方案：给定未来 N 天，**自动给出每日建议价**
  - 输入：历史同期出租率、当前库存进度（Booking Curve）、提前天数、周末/节假日、房型
  - 模型：`建议价 = 基线价 × 出租率系数 × 提前期系数 × 周末系数`（规则 + 轻量回归，可解释）
- **杀手锏：回测对比** —— 用历史数据跑一遍，给出「按建议价 vs 按原价」的 RevPAR 对比曲线
- 为什么这招好使：有图、有数、有算法、有商业价值，且**不是 CRUD**

> 答辩必带的图：建议价 vs 实际价 折线 + RevPAR 提升百分比。数字不需要夸张，可信就行。

### 牌 3：工程深度 —— 证明不是玩具

- **防超售**：Redis 分布式锁 + SQL 原子更新（`UPDATE ... WHERE total - sold >= ?`），不是"先查再写"
- **夜审**：单事务过账 + 幂等控制 + 失败不推进营业日 + 可重跑
- **账务**：余额恒等式由 SQL 保证，冲销/转账/拆账页都有据可查
- 讲这些是为了回答「你这个是不是就增删改查」

### 牌 4：工程形态 —— 一套代码多端

- uni-app 同时产出 H5 + 微信小程序 +（可选）支付宝小程序
- 后端统一 `/app-api`，多端复用
- 开源，可二开

## 四、演示设计（决定第一印象）

### 4.1 数据大屏（P2 交付，最优先）

一屏四区：
- 左上：今日核心指标卡（出租率 / ADR / RevPAR / 营收）
- 右上：实时房态网格（按楼层，颜色区分房态）
- 左下：近 30 天营收与出租率趋势
- 右下：今日预抵 / 预离列表 + 待办

配色走深色底 + 高对比，投屏好看。用 ECharts。

### 4.2 演示数据生成器

一键生成：
- 6 个月历史订单（含在住、已退、取消各种状态）
- 对应的账务明细、支付流水、夜审记录
- 客源/渠道分布、会员数据
- 目标：所有图表都有内容，且趋势「像真的」（有淡旺季、有周末高峰）

### 4.3 演示剧本（3 分钟走完一条线）

1. 客人打开小程序 → 选日期房型 → 下单 → 微信支付（Mock 成功）
2. 前台房态看板 → 看到新预订 → 办理入住 → 房态变色 → 自动生成房卡记录
3. 客人消费挂账 → 账页明细实时更新 → 余额显示
4. 夜审 → 房费自动过账 → 营业日推进
5. 老板打开大屏 → 看今日经营数据 + 智能定价建议

### 4.4 小程序体验版

- uni-app 编译，微信开发者工具预览 / 体验版
- 个人主体过不了「住宿服务」类目，**不上线，只演示**
- 答辩现场：投屏演示 + 提供体验版二维码

## 五、执行排期（重排后的三期）

| 期 | 内容 | 与原计划差异 |
|---|---|---|
| **P0 能开门** | 房价日历、账页、夜审、续住换房钟点房、交班发票、指标 | 不变（进行中） |
| **P1 面向客户** | 房价计划/渠道、预订引擎、**在线支付**、会员、自助入住退房、电子发票；**前端改 uni-app** | 加 uni-app |
| **P1.5 智能定价** | 定价建议模型 + 回测对比 + 前端展示 | **新增**（核心亮点） |
| **P2 演示与参赛包** | 数据大屏、演示数据生成器、演示剧本、多门店、协议单位 AR；公安/门锁/OTA 只做 Mock 展示 | **大幅裁剪 + 转向** |

P1.5 建议并进 P1 一起做（同一批接口，避免二次启动成本）。

## 六、答辩准备清单（P2 完成后做）

## 七、一条硬提醒

**不要为了功能数量牺牲演示质量。** 一个跑得顺、有数据、有大屏、讲得出创新点的系统，
分数远高于一个功能多但现场空白、卡顿、讲不清亮点的系统。
