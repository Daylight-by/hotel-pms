# 在另一台电脑上跑起来 —— 安装与配置清单

> 目标：把「酒店 PMS」从开发机搬到另一台 Windows 电脑（答辩机 / 队友机）。
> 两种情况分开看：**只演示** 和 **继续开发**，前者可以少装一半东西。

---

## 一、需要装什么

### 场景 A：只用来演示（答辩推荐）

| 组件 | 版本要求 | 是否必须装 | 说明 |
|---|---|---|---|
| **JDK** | 21（17 也行，本项目用 21 编译） | 必须 | 只跑 jar 的话装 **JRE 21** 就够，体积小一半 |
| **MariaDB / MySQL** | MariaDB 10.6+ 或 MySQL 8 | 必须 | **可以免安装**：开发机上的便携版整个目录拷走即可（见第三节） |
| **Redis** | 5.0+ | 必须 | 同上，便携版可拷（47M） |
| **Node.js + pnpm** | Node ≥ 20.19，pnpm ≥ 8.6 | **可选** | 只有用 `pnpm dev` 跑前端才需要。若用构建好的 `dist`，可以不装（但要 nginx 之类托管） |

### 场景 B：要在新电脑上继续改代码

在场景 A 的基础上再加：

| 组件 | 版本 | 用途 |
|---|---|---|
| **Maven** | 3.8+（开发机 3.9.16） | 编译打包后端 |
| **VS Code** | 任意 | 看源码。**注意：开着 VS Code 时 `mvn clean` 会被 Java 语言服务挡住** |
| **微信开发者工具** | 最新 | 只有要预览/改小程序端才需要 |

> 后端编译产物 `yudao-server/target/yudao-server.jar` 已经打好，
> **只演示的话新电脑完全不用装 Maven**。

## 二、三步配置

### 第 1 步：建库并导入数据

```sql
CREATE DATABASE `ruoyi-vue-pro` DEFAULT CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
```

按**这个顺序**导入（顺序不能乱，后面的依赖前面的）：

```
sql/mysql/ruoyi-vue-pro.sql   ← 芋道基础库（系统/权限/租户，2.4MB）
sql/mysql/hotel.sql           ← 酒店 P0 表（房型/房间/账页/夜审…）
sql/mysql/hotel-t1.sql        ← 渠道 / 房价计划 / 占位 / 智能定价
sql/mysql/hotel-t2.sql        ← 会员 / 支付单 / 发票申请
sql/mysql/hotel-t3.sql        ← C 端房型补充字段
sql/mysql/hotel-t4.sql        ← 大屏 / 报表 / 审计 / 演示数据
```

命令行导入示例（MariaDB 便携版）：

```bat
D:\tools\db\mariadb\mariadb-11.4.4-winx64\bin\mariadb.exe -uroot -p123456 --default-character-set=utf8mb4 ruoyi-vue-pro < sql\mysql\ruoyi-vue-pro.sql
```

> ⚠️ 这些建表语句带 `DROP TABLE IF EXISTS`（芋道惯例），**重复导入会清空数据**。
> 演示数据想保留就别重复导。

### 第 2 步：确认连接配置

配置文件：`yudao-server/src/main/resources/application-local.yaml`

```yaml
server:
  port: 48080                      # 后端端口
spring:
  datasource:
    dynamic:
      datasource:
        master:
          url: jdbc:mysql://127.0.0.1:3306/ruoyi-vue-pro?...
          username: root
          password: 123456
  data:
    redis:
      host: 127.0.0.1
      port: 6379
```

新电脑上如果数据库密码/端口不一样，**改这里**。如果完全一致，一个字都不用动。

> ⚠️ 注意：这个配置打进了 jar 里。改完 yaml 必须**重新打包**才生效
> （或者启动时用 `--spring.datasource.dynamic.datasource.master.password=xxx` 覆盖）。

### 第 3 步：启动

严格按这个顺序，数据库和 Redis 必须先起来：

```bat
:: 1) MariaDB（若已注册为服务：net start MariaDB）
:: 2) Redis
D:\tools\db\redis\redis-server.exe D:\tools\db\redis\redis.windows.conf

:: 3) 后端（约 30-60 秒，看到 Started YudaoServerApplication 才算好）
java -jar yudao-server\target\yudao-server.jar

:: 4) 前端（另开一个窗口）
cd yudao-ui\yudao-ui-admin-vue3
pnpm dev
```

然后浏览器打开 **http://localhost:5173**，账号 `admin` / `admin123`，租户填 `芋道`。

## 三、免安装方案：便携包（最省事，推荐答辩用）

开发机上 MariaDB、Redis 都是**便携版**，可以直接整个目录复制，新电脑不用装数据库：

| 目录 | 体积 | 说明 |
|---|---|---|
| `D:\tools\db\mariadb` | 281 MB | MariaDB 11.4.4 便携版 |
| `D:\tools\db\redis` | 47 MB | Redis 5.0.14 便携版 |
| `D:\tools\db\data` | 172 MB | **数据库文件本身，里面已经是导好的演示数据** |

复制 `D:\tools\db` 整个目录到 U 盘（约 500 MB），在新电脑上启动这两个 exe 即可，
连"第 1 步建库导数据"都省了——数据是跟着走的。

## 四、五个必踩的坑

| 坑 | 现象 | 怎么办 |
|---|---|---|
| **前端写死了后端地址** | 打开页面能登录但接口全挂 | `yudao-ui/yudao-ui-admin-vue3/.env.local` 里 `VITE_BASE_URL='http://localhost:48080'`。**后端必须跑在 48080**，否则要改这个文件重新 `pnpm build:local` |
| **端口被占** | `Port 48080 already in use` | 新电脑若装了别的东西占 48080，要么停掉它，要么改 yaml 里的 `server.port`（但前端也要同步改） |
| **Node 装完前端起不来** | Vite 崩溃 / `SAFE_DELETE_BULK_CONFIRM_REQUIRED` | 用 `env -u NODE_OPTIONS ... pnpm dev` 启动 |
| **pnpm 装依赖失败** | node_modules 只有空目录 | 项目里 `pnpm-workspace.yaml` 已设 `nodeLinker: hoisted`，**别改回 symlink** |
| **跑 `mvn clean` 失败** | 提示文件被占用 | 关掉 VS Code 再编，或加 `-Dmaven.clean.failOnError=false` |

## 五、验收：怎么确认新电脑真的好了

```bat
:: 后端健康检查（返回 200 且有 accessToken 即正常）
curl -X POST http://localhost:48080/admin-api/system/auth/login ^
  -H "Content-Type: application/json" ^
  -d "{\"username\":\"admin\",\"password\":\"admin123\",\"tenant-name\":\"芋道\"}"
```

更彻底的做法是把 `script/acceptance/` 一起拷过去跑一遍：

```bat
python script\acceptance\run_all.py --phase p1
```

全绿 = 94 项功能都通了（baseline 24 + P0 33 + P1 37）。
跑之前记得先用 `D:\AAA\_reset_demo.sql` 复位数据（夜审有「一天一次」语义）。

> 注意：跑验收脚本前要 `unset http_proxy https_proxy HTTP_PROXY HTTPS_PROXY`，
> 否则 localhost 请求会被代理拦截，返回 502。
