# P1 ·「面向客户」—— 开放直销与在线交易

> 先读 [`00-总纲与派发说明.md`](./00-总纲与派发说明.md) 第 2 节（环境与规范）与第 4 节（通用 DoD）。
> **前置依赖：P0 已验收通过**（房价日历、账页、夜审、营业日均可用）。

## 0. 为什么是这些

P0 做完系统只能内部用，客人还是打电话或走 OTA。P1 的目标是让酒店**自己能卖房**：客人打开手机就能查房态房价、下单、付钱、拿发票。核心是四件事——**房价计划与渠道**（不同渠道卖不同价、不同政策）、**预订引擎**（可售查询 + 库存扣减 + 防超售）、**在线支付**、**自助服务**（查订单 / 自助入住退房 / 电子发票）。

P1 做完 = 酒店有一个能真收钱的直销渠道，不再只依赖 OTA。

### 2.6 智能定价建议（P1.5 · 核心创新点，必做）

> 这是本项目**唯一的算法亮点**，也是答辩重点。必须做出「可解释 + 能回测」两件事，
> 否则就只是个 CRUD，评委一句「你这个创新在哪」就顶回来了。

包：`controller/admin/pricing`、`service/pricing`、`dal/dataobject/pricing`、`dal/mysql/pricing`

DO：`PriceSuggestionDO`（`hotel_price_suggestion`）、`PriceBacktestDO`（`hotel_price_backtest`）

**`PriceSuggestionService`**
```java
// 生成未来 N 天各房型的建议价（幂等：同 roomType+date 覆盖更新）
int generateSuggestions(Long roomTypeId, LocalDate begin, LocalDate end);
// 查询建议（前端日历用）
List<PriceSuggestionRespVO> listSuggestions(Long roomTypeId, LocalDate begin, LocalDate end);
// 采纳建议：把建议价写回房价日历，并记录 adopted_price

// 忽略建议
void ignore(Long suggestionId);
// 回测：拿历史区间跑一遍，返回「原价 vs 建议价」的 RevPAR 对比
PriceBacktestRespVO runBacktest(PriceBacktestReqVO reqVO);
PageResult<PriceBacktestRespVO> getBacktestPage(PriceBacktestPageReqVO reqVO);
```

**算法（可解释优先，不要上黑盒模型）**

```
建议价 = 基线价 × 出租率系数 × 提前期系数 × 周末系数
```

| 系数 | 取值逻辑 | 说明 |
|---|---|---|
| 出租率系数 `occFactor` | 历史同期出租率 < 40% → 0.85；40~70% → 1.0；> 70% → 1.15；> 85% → 1.30 | 淡季降价保量，旺季提价 |
| 提前期系数 `advanceFactor` | 提前 > 30 天 → 0.90（早鸟）；7~30 天 → 1.0；< 3 天且库存进度低 → 0.90（尾房甩卖）；< 3 天且库存紧张 → 1.20 | 随预订曲线调整 |
| 周末系数 `weekendFactor` | 周五/周六 → 1.20；节假日 → 1.35；其余 1.0 | 休闲需求溢价 |
| 安全边界 | 建议价下限 = 基线价 × 0.7，上限 = 基线价 × 1.5 | 防止离谱价格 |

- `reason` 必须生成**人话**，例如：「历史同期出租率 78%，属旺季；距入住还有 5 天且已售 60%，建议上调 15%」
- 结果四舍五入到整数元（人民币习惯）

**回测（`runBacktest`，答辩杀手锏）**
- 取历史区间每日：原价 = 当日日历价；建议价 = 模型算出的价
- 用**实际需求弹性假设**估算销量（弹性系数可配置，默认 -1.2，写在代码常量里并注明是假设）
- 分别算 RevPAR：`原价 RevPAR` vs `建议价 RevPAR`，给出 `upliftRate`
- 返回逐日明细（日期 / 原价 / 建议价 / 出租率 / RevPAR），前端画对比折线

> **诚实性要求**：回测基于弹性假设，代码注释和答辩 PPT 里必须写明这是假设，
> 不能号称"真实提升"。评委问起来答得上来才是加分，吹过头会翻车。

| 方法 | 路径 | 权限 |
|---|---|---|
| POST | `/hotel/pricing/generate` | `hotel:pricing:create` |
| GET | `/hotel/pricing/list?roomTypeId=&beginDate=&endDate=` | `hotel:pricing:query` |
| PUT | `/hotel/pricing/adopt?id=&price=` | `hotel:pricing:update` |
| PUT | `/hotel/pricing/ignore?id=` | `hotel:pricing:update` |
| POST | `/hotel/pricing/backtest` | `hotel:pricing:query` |
| GET | `/hotel/pricing/backtest/page` | `hotel:pricing:query` |

5. 预订晚数小于 `min_nights` → `1003004203`。

### 4.2 预订引擎
6. `availability` 返回每个房型的最低可售价与剩余房量；关房日期的房型不返回。
7. 库存剩 1 时，A 创建 hold 成功后 B 再创建 → `1003004221`。
8. hold 15 分钟后过期，此时 submit → `1003004222`；定时任务把状态置 40。
9. submit 后 `sold_inventory` 正确 +1，`hotel_booking_hold.status=20`。
10. 未登录提交订单（仅手机号）成功，订单 `status=10 待支付`。

### 4.3 支付
11. `createPayOrder` 返回 `payOrderNo` 与 `payParams`；`getPayResult` 返回 `status=10`。
12. mock 支付成功后：`hotel_pay_order.status=20`、订单 `status=20`、账页新增贷方明细、`paid_amount` 正确。
13. 同一回调重复推送两次 → 幂等，账页只入一次账。
14. 退款后 `pay_order.status=40`，账页余额正确回退。

### 4.4 会员与自助
15. 手机号登录成功返回 token；重复手机号注册 → `1003004242`。
16. 入住退房后积分按实付金额增加，积分流水有记录。
17. 积分不足时兑换 → `1003004243`。
18. 已支付且当日的订单自助入住成功 → 订单 `status=30`，房态 20。
19. 非当日订单自助入住 → 失败（返回明确错误）。
20. 自助退房 → `status=40`，房态 30，生成清洁任务。

### 4.5 发票
21. 会员提交电子发票申请 → `hotel_invoice_apply.status=10`；管理端开具后 `=20` 且生成发票记录。
22. 申请金额超过订单消费合计 → 驳回或报错。
