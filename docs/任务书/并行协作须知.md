# ⚠️ 并行协作须知（T1–T5 必读，违反即返工）

## 一、你现在的处境（先搞清楚这件事）

**你正在和另外 3–4 个 agent 在同一台电脑、同一个 Git 仓库、同一个数据库上同时开发。**

```
D:\AAA\hotel-management-yudao      ← 同一个目录，大家共写
MariaDB 127.0.0.1:3306 / ruoyi-vue-pro   ← 同一个库，大家共写
```

这意味着：**任何「全局操作」都会毁掉别人的工作。** 你跑一条 `git checkout .`，别人几小时的代码就没了；你跑一次 `mvn clean`，别人的服务就崩了。

所以下面 7 条是硬性约束，不是建议。

---

## 二、七条铁律

### 铁律 1：禁止一切 git 写操作

```bash
git checkout .          # ❌ 会丢弃所有人的改动
git reset --hard        # ❌ 同上，灾难性
git stash               # ❌ 会把别人的改动一起藏起来
git clean -fd           # ❌ 会删掉别人新建的文件（包括它们的 SQL、页面）
git add / git commit / git push   # ❌ 不要提交，由派发者统一合并
```

**只允许只读的 git 命令**：`git status`、`git diff`、`git log`。

### 铁律 2：禁止修改公共文件

这些文件多个包都要用，谁改谁负责冲突：

| 文件 | 说明 |
|---|---|
| `sql/mysql/hotel.sql` | **绝对禁止**。你只写自己的 `sql/mysql/hotel-tN.sql` |
| `enums/ErrorCodeConstants.java` | 禁止直接改。在交付说明里**列出你要的错误码清单**，由派发者合并 |
| `pom.xml` / `yudao-server/pom.xml` / `yudao-module-hotel/pom.xml` | 禁止改（除非确实要加依赖，先在交付说明里说明） |
| `application.yaml` / `application-local.yaml` | 禁止改。你自己的配置项写进**新建的** `application-hotel-tN.yaml` 并在交付说明里说明 |
| `src/utils/hotel.ts` | 前端公共枚举。**只有 T1 可以改**（订单状态扩容），其它包只读 |
| `src/router/modules/remaining.ts` | 禁止改。菜单走数据库 `system_menu` 配置 |
| `yudao-module-hotel/.../enums/OrderStatusEnum.java` 等公共枚举 | 只有 T1 可改，其它包只读 |

### 铁律 3：禁止 `mvn clean`

```bash
mvn clean package        # ❌ 删掉 target，正在运行的别人的实例会崩
```

**正确做法**：
```bash
mvn -pl yudao-server -am package -DskipTests -Dmaven.clean.failOnError=false
```
只 `package`，不 `clean`。如果 Maven 报 target 被占用，**等 10 秒重试**，不要强删。

### 铁律 4：禁止全局格式化 / 批量重构

```bash
npx prettier --write src/         # ❌ 会改写包含别人代码的所有文件
npm run lint -- --fix             # ❌ 同上
```

只格式化**你自己新建的文件**。别人的文件 diff 不要动。

### 铁律 5：只碰自己的目录

对照你包里的「号段」章节。**越界修改别人目录 = 返工**。
特别地，不要"顺手优化"别人的代码——看着不顺眼也留着，那是别人的活。

### 铁律 6：SQL 只写自己的文件

- 你新建 `sql/mysql/hotel-tN.sql`
- 里面只放**你自己包负责的表**
- 表名、菜单 ID、错误码必须落在你包分配到的号段内
- **不要执行** `DROP TABLE IF EXISTS hotel_room` 这类会清空别人数据的语句

### 铁律 7：禁止清库 / 全表删除

```sql
TRUNCATE TABLE hotel_order;      # ❌ 别人正在用它自测
DELETE FROM hotel_guest;         # ❌ 同上
```

自己造的测试数据，用**带包名前缀**的标识（如住客名 `T1测试客`、`T4-demo`），
清理时只删自己前缀的。

需要校验页面能否编译时，用 curl：
```bash
curl -s -o /dev/null -w "%{http_code}" "http://localhost:5173/src/views/hotel/xxx/index.vue"
```

**自测完请停掉自己的实例**，把端口和内存腾出来。

## 四、构建冲突怎么办

| 现象 | 原因 | 处理 |
|---|---|---|
| `target` 目录被占用 / 文件锁 | 别人在同时构建 | 等 10 秒重试，**不要删 target** |
| 构建成功但类找不到 | 别人刚改了公共类 | 重新 `package`，不 clean |
| 启动报 `Port xxx already in use` | 端口被占 | 换你的分配端口，不要 kill 别人的进程 |
| 数据库里出现不认识的测试数据 | 别的 agent 在自测 | 正常，别删 |
