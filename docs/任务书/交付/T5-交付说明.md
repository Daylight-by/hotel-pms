# T5 · 商业化横切 交付说明

> 交付范围：多门店与数据权限、协议单位 AR、公安/门锁/读卡/OTA 四个 Mock 展示层。
> 本包按任务书要求**最后开工**，SQL 与代码均在 T1–T4 交付之后完成。

## 一、交付内容

### 1. 后端

| 模块 | 内容 |
|---|---|
| 门店 | `hotel_store` 增删改查、门店列表/分页、编码唯一校验、停业状态 |
| 门店数据权限 | `StoreContext`（ThreadLocal）+ `StoreContextInterceptor`（请求头 `store-id`）+ `StoreDataPermissionRule`（芋道数据权限插件，自动给所有 `hotel_*` 表追加 `store_id`）+ `StoreInsertInterceptor`（INSERT 自动填充当前门店） |
| 协议单位 AR | 账户 CRUD、挂账、额度校验、生成结算单、结算收款、挂账明细/结算单分页 |
| 公安上传 | 日志、分页、统计、手动重试、每 60 秒自动重试（最多 5 次）、`MockPsbClient`；入住/退房/换房自动落日志 |
| 门锁 | 发卡/补卡/销卡/续卡日志、`MockLockClient`；入住发卡、退房销卡、续住续卡 |
| 身份证读卡 | `/hotel/device/id-card/parse`（Mock + 校验位解析）+ 前端「读取身份证」按钮（优先连 `ws://127.0.0.1:17888`，失败回退后端 Mock） |
| OTA | 配置 CRUD、Mock 拉单（按天幂等）、推房价、OTA 订单映射分页 |
| 操作审计 | T4 已有切面，本包补齐 `store_id` 写入；AR 挂账/结算/收款增加 `@HotelOperationLog` |

### 2. 前端

新增页面：`hotel/store`、`hotel/psb`、`hotel/lock`、`hotel/otaConfig`、`hotel/otaOrder`、`hotel/arAccount`、`hotel/arLedger`、`hotel/arSettlement`。

新增头部门店切换器：`src/layout/components/StoreSwitch.vue`，已挂入 `ToolHeader.vue`；选择结果写 `localStorage`，Axios 请求拦截器统一加 `store-id` 头，切换后刷新页面。

### 3. SQL

全部在 **`sql/mysql/hotel-t5.sql`**，不改 `sql/mysql/hotel.sql`：

- 25 张 `hotel_*` 表 `ADD COLUMN store_id bigint NOT NULL DEFAULT 0`（`hotel_store` 本身是门店主数据，不加）；常用表补 `idx_store` 索引。
- 新建：`hotel_store`、`hotel_psb_upload_log`、`hotel_lock_card_log`、`hotel_ar_account`、`hotel_ar_ledger`、`hotel_ar_settlement`、`hotel_ota_config`、`hotel_ota_order`。
- `hotel_operation_log` 由 T4 已建，本包只补 `store_id` 与数据回填，不重复建表。
- 演示数据：总店/西溪分店、分店房型房间、协议单位（额度 10000）、携程 Mock 配置、公安/门锁成功样例。
- 主店历史数据回填 `store_id=1`；分店演示数据 `store_id=2`，切店效果直观。

## 六、Mock 与演示说明

1. 公安、门锁、OTA、读卡全部走 Mock，无真实硬件/厂商账号；`mock_enabled` 默认开。
2. 读卡 Agent：`node script/idreader/agent.js --mock`，WS 端口 17888；前端连不上时自动回退后端 Mock。
3. OTA 拉单为「每配置每天一个固定单号」，重复点同步不会重复建单。
4. OTA 订单当前只做映射（`hotel_ota_order`），不自动生成本地 `hotel_order`，避免演示时占用真实房态；映射状态为「已建单」。
5. 自动重试：PSB 失败记录每 60 秒重试，最多 5 次；OTA 未开自动轮询，避免干扰验收计数。
