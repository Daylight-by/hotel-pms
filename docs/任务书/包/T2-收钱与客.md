## 三、支付层的硬性要求

- **不要重新引入 `yudao-module-pay`**（已被删除）。在 `hotel` 模块内自建轻量支付层
- 抽象 `PayClient` 接口，提供 `WxPayClient` / `AliPayClient` / **`MockPayClient`**
- **`MockPayClient` 是重点**：本项目没有企业主体，拿不到真实支付商户号，
  答辩靠 Mock 演示。配置项 `hotel.pay.mock-enabled: true` 默认开启，
  并提供 `POST /app-api/hotel/pay/mock-success` 一键模拟支付成功
- **回调必须幂等**：按 `channel_trade_no` 唯一键 + `pay_order.status` 判断，重复回调只入一次账

## 四、与 T1 的关系（注意，别踩）

- T1 在做预订引擎和 `hotel_order` 加字段，**你不要改 `hotel_order` 的业务字段**
- 你可以**只读**订单，用它的接口（若 T1 还没好，按 P1 §2.2 的契约先写，最后联调）
- 支付成功后写账页贷方明细、回写 `paid_amount`、订单转已确认——这些逻辑归你
