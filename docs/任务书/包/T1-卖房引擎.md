## 三、智能定价的额外要求（P1 §2.6 之外补充）

- 公式：`建议价 = 基线价 × 出租率系数 × 提前期系数 × 周末系数`，上下限 `[0.7x, 1.5x]`
- **`reason` 字段必须生成人话**，例：「历史同期出租率 78%，属旺季；距入住 5 天已售 60%，建议上调 15%」。这是答辩时给老板看的，不能是空话
- **回测必须做**：原价 vs 建议价的 RevPAR 对比，返回 `actualRevpar` / `modelRevpar` / `upliftRate`
- **诚实性**：回测用的需求弹性是**假设**（默认 -1.2），必须在代码常量里写明并加注释，不许伪装成真实提升

## 四、防超售的硬性要求（会被重点检查）

必须是 **SQL 原子更新**：
```sql
UPDATE hotel_room_daily_rate SET sold_inventory = sold_inventory + ?
WHERE id = ? AND total_inventory - sold_inventory >= ?
```
影响行数 0 就抛 `ERROR_HOLD_FAILED`。**严禁「先查再写」**——这是本项目工程深度的证明点之一，写错要返工。

hold 过期用定时任务释放（`@Scheduled`，5 分钟一次）。
