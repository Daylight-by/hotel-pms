## 二、你负责的四块

### 2.1 经营数据大屏（最高优先级）

页面：`src/views/hotel/dashboard/index`（菜单 20401）

一屏四区，深色底 + 高对比，**投屏要好看**：

| 区域 | 内容 |
|---|---|
| 左上 | 今日指标卡：出租率 OCC / 平均房价 ADR / RevPAR / 营收（带环比） |
| 右上 | 实时房态网格（按楼层，颜色区分 空闲/已入住/待清洁/维修） |
| 左下 | 近 30 天营收 + 出租率双轴趋势（ECharts） |
| 右下 | 今日预抵 / 今日预离列表 + 待办提醒 |

接口：`GET /admin-api/hotel/dashboard/overview`，返回上面所有数据（一次拿全，别让前端调十次）。

### 2.2 报表中心与审计（规格见 P2 §2.7 / §2.8）

- 日报 `/hotel/statistics/daily-report`：营业日、OCC、ADR、RevPAR、房费收入、其他收入、总营收、收款结构、在住/离店间夜、欠账余额
- 月报 `/hotel/statistics/monthly-report`
- 导出 `/hotel/statistics/export`（EasyExcel，返回 xlsx）
- 操作审计 `/hotel/operation-log/page`：AOP 切面 + `@HotelOperationLog` 注解，在入账、冲销、改价、夜审、换房、挂账、取消订单上织入，记录 before/after

### 2.3 演示数据生成器（★ 关键，没有它答辩必翻车）

**问题**：现在数据库是空的，答辩时所有图表空白。

**交付**：一键生成半年业务数据，让每个图表都有内容，且趋势要**像真的**。

接口：
```
POST /admin-api/hotel/demo/generate?months=6     # 生成
POST /admin-api/hotel/demo/clean                 # 一键清理（演示后可复原）
GET  /admin-api/hotel/demo/status                # 当前是否有演示数据
```

生成内容（6 个月，约 400–600 笔订单）：
- 订单：状态分布合理（已退房为主，少量在住/已取消/待确认）
- 每笔订单配账务明细（房费 + 随机杂费）、支付流水（现金/微信/支付宝/银行卡分布）
- 夜审记录（每个营业日一条）
- 清洁任务
- 会员数据（若 T2 的表已存在则写入，不存在则跳过，不要报错）

**真实感要求**（重要）：
- **淡旺季**：给月份加系数（如 7–8 月、10 月为旺季，1–2 月淡季）
- **周末高峰**：周五周六出租率明显高于工作日
- **价格浮动**：旺季价 ×1.2，淡季 ×0.85
- 不要均匀分布随机数——均匀的假数据一眼假

实现建议：写一个 `DemoDataService`，用固定随机种子（可复现），参数写在配置里。

### 2.4 演示剧本（★ 答辩用）

产出文档 `docs/演示剧本.md`，写清楚 3 分钟怎么走完一条线：

1. 客人打开小程序 → 选日期房型 → 下单 → 支付成功
2. 前台房态看板 → 看到新预订 → 办理入住 → 房态变色
3. 客人消费挂账 → 账页明细实时更新
4. 夜审 → 房费自动过账 → 营业日推进
5. 老板打开大屏 → 看今日经营数据 + 智能定价建议

每一步要写：**点哪个菜单、填什么、期望看到什么**。另附：
- 一键启动脚本 `script/demo-start.sh`（起后端 + 前端 + 灌数据）
- 答辩前 5 分钟检查清单
