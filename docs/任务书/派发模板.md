# 派发模板（复制给执行 agent 的开工指令）

> 每个执行 agent 只需要拿到「下面某一段 prompt + 对应任务书文件」。任务书本身已自包含，
> 不需要它回溯任何历史对话。派发时把 `{仓库路径}` 换成实际路径（本机是 `D:\AAA\hotel-management-yudao`）。

---

## P0 派发指令

```
你要在 {仓库路径} 这个芋道（yudao-boot-mini）二次开发项目里，完成酒店 PMS 的 P0 阶段开发。

【必读】
1. 先读 docs/任务书/00-总纲与派发说明.md —— 项目定位、仓库路径、启动命令、本机环境坑位、
   芋道编码规范、现有基线，全在里面，务必遵守第 2 节和第 4 节。
2. 再读 docs/任务书/P0-内部可用.md —— 这是你的完整任务书，包含建表 SQL、枚举、错误码、
   后端接口契约、前端页面、业务规则、测试用例、DoD 验收标准。

【产出要求】
- 建表/改表 SQL 追加到 sql/mysql/hotel.sql 末尾（只追加，禁止删除已有建表语句，
  禁止 DROP COLUMN，扩字段一律用 ALTER TABLE ADD COLUMN）。
- 后端按芋道分层写在 yudao-module-hotel 下，权限码 hotel:{模块}:{动作}。
- 前端页面写在 yudao-ui/yudao-ui-admin-vue3/src/views/hotel/ 与 src/api/hotel/。
- 新增菜单权限写入 sql/mysql/hotel.sql 的 system_menu（ID 段 20200+）。

【自验收】交付前必须自己跑通：
    python script/acceptance/check_baseline.py   # 必须全绿（不许破坏已有能力）
    python script/acceptance/check_p0.py         # 必须全绿
两项都要看到「失败 0」。有 FAIL 就继续修，不要提交半成品。

【禁止】
- 不要修改 P0 之前已有的表字段与接口签名。
- 不要用 Map.of()（芋道场景下 null 键会 NPE），用 new HashMap<>() / Collections.emptyMap()。
- LocalDate 出参必须加 @JsonFormat(pattern = "yyyy-MM-dd", timezone = "GMT+8")。
```

## 派发者（你）的收尾动作

每期交付回来后，按顺序做：

1. **跑脚本**：`python script/acceptance/run_all.py --phase pX`，看是否全绿。
2. **人工复核**（脚本查不到的部分）：
   - `sql/mysql/hotel.sql` 是否只追加、没删已有建表语句
   - 新表是否都带 `tenant_id` + 芋道四件套 + `deleted`
   - Controller 是否都带 `@PreAuthorize("@ss.hasPermission('hotel:xxx:yyy')")`
   - 错误码是否登记在 `ErrorCodeConstants`
   - 是否误删了原有模块（system/infra/hotel 之外的视图、路由、菜单）
3. **确认无回归**：`git diff --stat` 看改动范围是否合理。
4. 通过后合并，再派发下一期。
