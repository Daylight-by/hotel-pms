## 3. 关键设计决策（复核时请重点看）

1. **夜审「重复执行」判定**：夜审成功后营业日推进到 `D+1`；若 `D+1` 已超过自然日，再次触发
   一律返回 `1003004132`（等价「该营业日已完成夜审」——营业日不能跑到未来）。这样既满足
   DoD11（营业日推进）与 DoD12（重复夜审被拒），也符合真实 PMS「一天一次夜审」的语义。
2. **冲销口径**：明细状态 `10 有效 / 20 已冲销` 都计入账页合计，冲销通过一条**贷方负数明细**
   冲减，因此 `balance = total_charge - total_payment` 恒成立，且冲销后余额回到「冲销前 + 原金额」
   （与 DoD8 的断言一致）。转出（`30`）不计入合计，目标账页新增同额明细。
3. **库存口径**：剩余 = `total_inventory - sold_inventory`，占用用「条件 UPDATE」保证不为负；
   未维护的日期按房型基础价兜底、不阻断开单（避免前台因漏维护开不了单）。
4. **钟点房**：按房型 `hourly_price` 计价，`nights=0`，**不占房型日历库存**，只校验房型是否开放钟点房。
5. **账页开立时机**：订单 `confirm` 与 `check-in` 都会幂等确保主账页存在，前台不会出现「没账页记不了账」。

## 4. 环境相关的两个注意点

1. **`mvn clean package` 可能被文件锁挡住**：VS Code 的 Java 语言服务会持有各模块 `target` 目录句柄，
   Windows 下 `maven-clean-plugin` 删不掉目录会报 `Failed to clean project`。本次全量构建用的是
   `mvn -pl yudao-server -am clean package -DskipTests -Dmaven.clean.failOnError=false`（BUILD SUCCESS），
   或先关闭 VS Code 再执行原始命令。
2. **`LocalDateTime` 的序列化/反序列化**：芋道全局把 `LocalDateTime` 序列化为**时间戳**，
   且注册了只认时间戳的反序列化器（`@JsonFormat` 对它无效）。因此：
   - 出参：前端统一用 `dateFormatter` / `formatDate` 渲染时间戳；
   - 入参：钟点房的 `checkInTime` / `checkOutTime` 额外加了
     `@JsonDeserialize(using = LocalDateTimeDeserializer.class)`，可直接收 `yyyy-MM-dd HH:mm:ss`。
   - `LocalDate` 出参全部按规范加了 `@JsonFormat(pattern = "yyyy-MM-dd", timezone = "GMT+8")`。
