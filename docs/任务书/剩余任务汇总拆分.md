# 剩余任务汇总与并行拆分（P1 之后全部工作）

> 目标：把 P1、P1.5、P2 的全部剩余工作**一次性拆成 5 个可并行分发的任务包**。
> 各包同时开工 → 全部交付 → 由派发者（本 agent）统一验收修复。

---

## 一、拆包原则

1. **按内聚拆，不按期次拆**：把相关模块放一个包里，减少跨包依赖。
2. **横切的放最后**：「多门店」要给所有表加 `store_id`，必须最后做。
3. **SQL 物理隔离**：这是并行不打架的核心手段——**任何包都不许改 `sql/mysql/hotel.sql`**，
   各自新建 `sql/mysql/hotel-tN.sql`，由派发者按顺序合并导入。
4. **号段预先分配**：菜单 ID、错误码、表名、包路径全部事先定死，各包只用自己那段。
5. **公共文件禁止改**：`ErrorCodeConstants` 等公共文件由派发者最终合并，
   各包只在自己的 SQL 文件里登记号段并在交付说明中列出（避免多人改同一文件冲突）。

## 六、派发与验收流程

### 派发
1. 把 `包/TN-xxx.md` 发给对应 agent（本机可直接给路径，让它自己读）
2. 每个包都要求它**必读** `00-总纲与派发说明.md`（环境、坑位、编码规范）
3. T1–T4 同时发；T5 等前面交付后再发

### 验收（派发者执行）
```bash
python script/acceptance/run_all.py --phase p0   # 先确保 P0 与基线不回归
# 再按包跑对应的补充检查
```

### 问题分级与处理

| 级别 | 判定 | 处理 |
|---|---|---|
| **小问题** | 字段缺失、枚举不同步、页面 500、权限码没下发、SQL 字段名不一致、金额精度、日期格式 | **派发者直接修**，不返工 |
| **大问题** | 核心链路不通（下单/支付/夜审）、防超售没有用原子更新、账页余额算错、模块整体缺失、改了禁止碰的文件、SQL 写进了 hotel.sql | **整包返工**，退回给原 agent 重做 |

### 验收后合并
- 派发者按 T1 → T2 → T3 → T4 → T5 顺序合并各 `hotel-tN.sql` 到主 `hotel.sql`
- 合并 `ErrorCodeConstants`、菜单、路由
- 全量跑 `run_all.py --phase all`

### 集成验收时的归位规则（派发者执行，别忘）

各 agent 的菜单 SQL 仍写 `parent_id=20000`（它们的包在分组前已发出，不知道这次重组）。
**集成验收合并各 `hotel-tN.sql` 后，必须按号段把新菜单归位**：

```sql
-- T1 渠道/房价计划/智能定价（20300-20349）→ 收益营销
UPDATE system_menu SET parent_id=20501 WHERE id BETWEEN 20300 AND 20349 AND deleted=0 AND parent_id=20000;
-- T2：会员(→20501)、支付单/发票申请(→20502)，按 name 判断
-- T4 大屏/报表/审计（20400-20449）→ 数据报表
UPDATE system_menu SET parent_id=20503 WHERE id BETWEEN 20400 AND 20449 AND deleted=0 AND parent_id=20000;
-- T5 到时定：AR→20502，公安/门锁/OTA→可新建「扩展对接」20504
```

注意：合并 SQL 时如果重导了带菜单 INSERT 的 `hotel-tN.sql`，菜单会回到 20000 下，
**导入后统一跑一遍归位脚本**（放 `script/acceptance/` 或手动执行）。
