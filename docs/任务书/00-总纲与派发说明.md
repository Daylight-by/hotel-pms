## 1. 项目定位

基于 [芋道 yudao-boot-mini](https://github.com/yudaocode/yudao-boot-mini)（MIT 协议）二次开发的**酒店管理系统（PMS, Property Management System）**。

- 保留芋道的：多租户、RBAC 权限、用户/角色/菜单/部门/岗位、字典、文件、代码生成、API 日志、定时任务。
- **已删除**芋道自带的：AI、BPM 工作流、CRM、ERP、财务 FMS、HRM、IM、IoT、商城 Mall、会员 Member、MES、公众号 MP、OA、支付 Pay、PMS(芋道自有物业模块)、报表 Report、WMS。这些与酒店业务无关，前端源码与数据库菜单均已清除。
- 自研 `hotel` 业务模块，完全按芋道分层规范编写。

### 2.3 本机环境坑位清单（**已踩过，禁止重复踩**）

| 坑 | 现象 | 解法 |
|---|---|---|
| **LocalDate 序列化成 `[2026,10,21]`** | 芋道全局 `spring.jackson.write-dates-as-timestamps=true` | 所有 RespVO 的 `LocalDate` 字段必须加 `@JsonFormat(pattern = "yyyy-MM-dd", timezone = "GMT+8")` |
| **`Map.of()` 遇 null 键抛 NPE** | 查询出 id→name 映射后 `map.get(null)`（如未指派保洁的 assigneeId）抛异常 → 接口 500 | 一律用 `new HashMap<>()`，空值时用 `Collections.emptyMap()`，**禁止** `Map.of()` |
| **MyBatis-Plus `LambdaQueryWrapperX` 泛型陷阱** | 继承来的 `eq/lt/gt/in` 返回父类型 `LambdaQueryWrapper`，链式再接 `neIfPresent` 编译失败 | 先链式构造基础条件，再用 `if (x != null) wrapper.ne(...)` 单独追加，不要一路链式到底 |
| **后端端口 8857 被占用** | `Port 8857 already in use` | 必须显式 `--server.port=48080` |
| **前端端口 80 被 Steam++ 占用** | vite 起不来 | 必须显式 `--port 5173` |
| **Vite 启动崩溃 `SAFE_DELETE_BULK_CONFIRM_REQUIRED`** | WorkBuddy 通过 `NODE_OPTIONS=--require=...node-language-shim.cjs` 注入钩子 | 用上面的 `env -u NODE_OPTIONS ...` 方式启动 |
| **无符号链接权限** | pnpm 装完 `node_modules` 只有 12 个空 @scope 目录，缺 vite | `pnpm-workspace.yaml` 已设 `nodeLinker: hoisted` + `allowBuilds`，**不要**改回 symlink |
| **批量删除被 safe-delete 拦截** | `rm -rf` / `mv` 报 Permission denied 或 bulk-confirm | 用 PowerShell `Remove-Item -Recurse -Force`；脚本报 `trash-failed` 常是误报，以 `Test-Path` 复核为准 |
| **`LocalDateTime` 反序列化只认时间戳（P0 实测）** | 芋道全局把它序列化成时间戳，且**反序列化只接受时间戳**，`@JsonFormat(pattern=...)` 对入参**无效**，收到 `yyyy-MM-dd HH:mm:ss` 会报错 | 入参字段必须加 `@JsonDeserialize(using = LocalDateTimeDeserializer.class)`；出参交给前端 `formatDate` 渲染。**T1/T2 涉及支付时间、发票时间、钟点房时段时必踩** |
| **`mvn clean package` 被 VS Code 挡住** | VS Code Java 语言服务持有 `target` 目录句柄，clean 失败 | 用 `-Dmaven.clean.failOnError=false`，或构建前关掉 VS Code |
| **`sql/mysql/hotel.sql` 重复导入会清空数据** | 建表语句带 `DROP TABLE IF EXISTS`，是芋道惯例（幂等重建） | 演示数据想保留就**不要重复导入**；需要复位演示数据用 `D:\AAA\_reset_demo.sql` |
| **夜审「一天一次」语义** | 夜审成功后营业日推进到 D+1；若 D+1 已超过自然日，再次触发返回 `1003004132`。因此连跑两次 `check_p0.py` 第二次会卡在 DoD11 | 不是 bug。跑第二次前用 `D:\AAA\_reset_demo.sql` 复位数据 |
| **后台开单的状态与账页（派发者已修，2026-10-21）** | P0 原实现 `createOrder` 落 `10 待确认`，P1 把 10 语义改成「待支付」后，后台开单被显示成「待支付」；且**主账页只在 `confirmOrder` 里开**，直接改落 20 会跳过开账页，导致挂账/收款/结账全断 | 已按 P1 规格修复：`createOrder` 落 `20 已确认` + 调 `folioService.ensureFolioForOrder()` 开主账页；`confirmOrder` 改为**幂等**（已确认则仅保底补开账页并返回）。**T4/T5 若写订单相关代码，按「新建订单 = 20 + 账页已存在」这个前提来** |
| **C 端下单与后台开单是两条不同链路** | C 端走 `BookingServiceImpl.submitBooking` 落 `10 待支付`（正确）；后台走 `OrderServiceImpl.createOrder` 落 `20 已确认` | 不要统一成一个方法，两者语义不同 |
| **错误码号段已实际分配（勿再改动）** | 并行包各自建了独立常量文件避免冲突 | P0: 4001–4132；T1: 4201–4213 / 4221–4222 / 4231–4233；T2: 4235–4260；T4: 4261–4280。**新错误码必须落在自己号段内**，合并前会查重（当前 79 个全唯一） |

### 2.4 芋道编码规范（**必须遵守，验收会查**）

**分层（自上而下）**
```
controller/admin/{模块}/{Xxx}Controller.java          只做参数校验 + 调 service + 包 CommonResult
  └─ controller/admin/{模块}/vo/{Xxx}PageReqVO.java   分页查询入参（继承 PageParam）
     controller/admin/{模块}/vo/{Xxx}SaveReqVO.java   新增/修改入参
     controller/admin/{模块}/vo/{Xxx}RespVO.java      出参
service/{模块}/{Xxx}Service.java                      接口
  └─ service/{模块}/{Xxx}ServiceImpl.java             实现，@Service
dal/dataobject/{模块}/{Xxx}DO.java                    @TableName + extends TenantBaseDO
dal/mysql/{模块}/{Xxx}Mapper.java                     extends BaseMapperX<XxxDO>
enums/{Xxx}Enum.java                                  枚举，值用 10/20/30 递增留间隔
enums/ErrorCodeConstants.java                         错误码，统一在此登记
```

**硬性要求**
1. DO 必须 `extends TenantBaseDO`（自动带 tenant_id / creator / create_time / updater / update_time / deleted）。
2. 建表必须带 `tenant_id bigint NOT NULL DEFAULT 0` 及芋道四件套（`creator`/`create_time`/`updater`/`update_time`）和 `deleted bit(1) DEFAULT b'0'`。
3. Controller 权限注解：`@PreAuthorize("@ss.hasPermission('hotel:{模块}:{动作}')")`，动作 ∈ `query|create|update|delete|export|audit`。
4. 返回统一 `CommonResult<T>`，分页 `CommonResult<PageResult<XxxRespVO>>`。
5. 业务异常必须走 `throw ServiceExceptionUtil.exception(ERROR_CODE_XXX)`，错误码登记在 `ErrorCodeConstants`（hotel 模块号段 `1-003-004-xxx`）。
6. 金额一律 `BigDecimal`，**禁止** double/float；比较用 `compareTo`，不要用 `equals`。
7. 分页/列表查询走 `LambdaQueryWrapperX` 的 `likeIfPresent` / `eqIfPresent` / `betweenIfPresent`。
8. 新增表必须同步在 `sql/mysql/hotel.sql` 追加 `CREATE TABLE`（**保留已有建表语句**，只追加，不要重写整个文件导致丢演示数据）。
9. 新增菜单/权限必须在 `sql/mysql/hotel.sql` 追加 `INSERT INTO system_menu`（hotel 菜单 ID 段 **20000–20199**，P1/P2 可扩到 20200+）。
10. 前端新增页面必须配 `@/api/hotel/{模块}/index.ts` + `@/views/hotel/{模块}/index.vue`，并在后端 `system_menu` 里配 `component` 为 `hotel/{模块}/index`。

## 3. 三期总览

| 期 | 目标 | 一句话定义 | 依赖 | 预估工作量 |
|---|---|---|---|---|
| **P0** | **能开门** | 单店内部可用：房价日历 + 账务账页 + 夜审营业日 + 续住换房钟点房 + 交班发票 + 真实经营指标 | 现有基线 | 大 |
| **P1** | **面向客户** | 对外开放直销：房价计划/渠道 + 预订引擎 H5/小程序 + 在线支付 + 自助入住 + 电子发票 | P0 | 大 |
| **P2** | **商业化** | 合规与生态：公安上传 + 身份证读卡 + 门锁 + OTA 直连 + 协议单位 AR + 多门店 | P0+P1 | 大 |

### 派发建议

- **串行派发**：P0 → P1 → P2。每期之间有数据模型依赖（P1 的房价计划依赖 P0 的日历价，P2 的多门店依赖全表 store_id）。
- 若并行，最多允许 **P0 内部按模块并行**（房价日历 / 账务账页 / 夜审 / 订单操作 / 交班发票 / 报表 六块可并行），但**建表 SQL 必须由一个 agent 统一合并**到 `sql/mysql/hotel.sql`，避免 ID 与字段冲突。
- 每个执行 agent 交付前必须自跑对应验收脚本，全绿后再提交。

## 4. 通用 DoD（每一期都必须满足，否则不予验收）

1. **编译**：`mvn -pl yudao-server -am clean package -DskipTests` 成功打出 jar。
2. **启动**：后端 48080 能起，无 ERROR 级异常；前端 `pnpm dev --port 5173` 能起。
3. **页面**：新增/修改的 Vue 页面用 curl 请求 Vite 编译地址返回 **HTTP 200**（编译无错），例如：
   ```bash
   curl -s -o /dev/null -w "%{http_code}" "http://localhost:5173/src/views/hotel/rate/index.vue"
   ```
4. **接口**：全部新增接口在登录后返回 `code == 0`，且字段与任务书契约一致。
5. **权限**：新增菜单 + 权限码已写入 `system_menu`，且 `hotel:*` 权限码能被 `/admin-api/system/auth/get-permission-info` 返回。
6. **SQL**：新增建表语句已追加进 `sql/mysql/hotel.sql`，且**全新库执行整个文件无报错**。
7. **无回归**：`script/acceptance/check_baseline.py` 全绿（保护已打通的基线链路）。
8. **无破坏**：未删除/修改 `2.5` 基线中已有的表字段与接口签名；确需改字段必须走 `ALTER TABLE ... ADD COLUMN`（**禁止 DROP COLUMN**，避免丢数据）。
